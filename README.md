> 不绑定单一平台，不把提示词藏起来。服务商、回退链、画廊和通知，都在 WebUI 里掌控。

## 功能

- 文生图（`generate_image`）、改图（`edit_image`）、自拍/人像生成（`generate_selfie`）、文生视频/图生视频（`generate_video`）、重发结果（`resend_image`）、翻旧图（`find_image`）六个工具；批量不另设工具，直接在 `generate_image` 里传多张。
- 批量生成：给一组提示词直接出图，也可以只说一句需求，由插件拆成多条提示词、各配一个画幅，一次出多张。
- 4 种服务商模板：标准生图接口、对话接口出图、自定义完整地址、视频接口。
- 功能链路：每个功能可以排一串服务商，前一家失败或画幅不支持时自动换下一家。
- 全局队列：并行数、排队上限、每用户图片/视频上限、批量上限都能调；失败的任务不占并行位置。
- 画廊：生成的图自动留档，收藏的不会被自动清理；图片和自拍各 50 张 / 14 天，视频 20 张 / 14 天，三档互不挤占。
- 图片记忆：每次生成都会拿到一个编号，改图和图生视频可以直接用编号指定原图；也能按描述翻出这个会话画过的东西。
- 完成通知：发完图后补一轮结果，成功、失败、部分成功共用一条「结果通知提示词」，事实带任务号与状态；模板留空就只把事实交给模型。图片一条最多 4 张，超了分条发。
- WebUI：概览、服务商、任务、画廊、设置五个页面，全部配置都在这里改，保存后立即生效。

## 要求

- Kira `>= 3.0.2`
- Python 依赖：`aiohttp`、`Pillow`（见 `requirements.txt`）

## 安装

1. 把整个 `kira_plugin_aiimg` 目录放进 Kira 的插件目录（和别的插件并排）：

   ```
   <Kira 目录>/plugins/kira_plugin_aiimg/
   ├── manifest.json
   ├── main.py
   ├── schema.json
   ├── core/
   ├── web/
   └── ...
   ```

2. 在 Kira 用的那个 Python 环境里装依赖：

   ```bash
   pip install -r plugins/kira_plugin_aiimg/requirements.txt
   ```

3. 重启 Kira（或在插件管理里重载），在插件列表里启用「AI 生图」。

成功的标志：侧边栏出现「AI 生图」，点进去能看到概览页；概览里的服务商是 0 家，说明插件已经跑起来，只差配置。如果侧边栏没有这一项，先看 Kira 的日志里有没有 `kira_plugin_aiimg` 的报错，再确认依赖是否装在了同一个 Python 环境里。

4. 打开插件页面，在「服务商」里添加至少一家能出图的服务商并保存。视频功能需要再配一家视频服务商。

## 配置服务商

在「服务商 → 连接」里点「新增」，先选接口类型，再按提示填：

| 接口类型 | 适合什么情况 | 必填 |
| --- | --- | --- |
| 标准生图接口 | 最常见的对接方式，生图和改图分开调用 | 接口地址、模型名 |
| 对话接口出图 | 把提示词发给对话模型，从回复里取图（Gemini 系和各类网关常用） | 接口地址、模型名 |
| 自定义完整地址 | 接口路径不标准，生图、改图各有一个完整网址 | 生图地址 |
| 视频接口 | 提交任务后按固定间隔查询结果 | 服务地址、模型名 |

常用字段说明：

- 接口地址：填到 `/v1` 这一层就行，后面的生图、改图路径会自动接上。
- 密钥：一行一个。填多个时轮流用，被服务商拒绝的那把会暂时停用。在服务商编辑页点「编辑」用列表编辑器维护：回车逐条添加，也可以「批量粘贴」一次贴多行。
- 默认画幅：写 `1024x1024`、`3:4 4K`、`2K` 这类都可以，留空按 `1024x1024`。
- 可选画幅：一行一个。只有服务商挑尺寸时才填，留空表示不限制。
- 比例映射：键是比例、值是画幅，用来指定某个比例优先用哪个尺寸，一般不用填。
- 额外请求参数：以 JSON 形式随请求发送，服务商有特殊参数时才需要。
- 代理地址、超时秒数、重试次数、图片格式：按需调整，默认值适用大多数情况。

每家服务商保存时都会校验，缺必填项或格式不对会直接提示。

## 功能链路

「服务商 → 功能链路」里，每个功能一行一家服务商，从上到下尝试：

- 文生图、改图、自拍、批量生图、视频各自独立。
- 右侧画幅可以留空，留空就用功能默认值。
- 服务商不支持改图、或者画幅不被接受时，会自动跳到下一家。
- 没有排顺序时，用第一个能用的服务商。

## 工具与队列

| 工具 | 说明 |
| --- | --- |
| `generate_image` | 文生图，参数 `prompt`、`provider`、`size`/`aspect_ratio`/`resolution`（画幅也可以直接写在提示词末尾，如 `1024x1024`、`3:4 4K`、`2K`）；要一次出多张就传 `prompts`、`brief` 或 `count`，可以带 `image` 参考图，`selfie=true` 时按自拍处理 |
| `edit_image` | 改图，使用当前消息、回复消息里的图片，或 `find_image` / 结果通知里的编号 |
| `generate_selfie` | 自拍/人像生成，基于「设置 → 自拍参考图路径」里的参考照片 |
| `generate_video` | 文生视频或图生视频；带图时用当前或回复消息里的图片，也可以给编号；可另给尾帧与音轨，没图时按设置先拍一张开场图 |
| `resend_image` | 重发结果，不重新生成；不传参数取本会话最近一次，也可以给编号；还能按描述或 `days_ago`/`date` 直接找并重发 |
| `find_image` | 按描述或类型翻这个会话画过的东西，只回清单不发图；支持 `days_ago`/`date` 限定日期 |

队列参数在「设置 → 队列」：并行数（默认 2）、排队上限（默认 16）、批量上限（默认 8）、批量并行（默认 2）、每人图片任务上限 / 视频任务上限（默认各 1）、记录保留小时数（默认 24）、重复请求合并秒数（默认 3，填 0 关闭）。

视频发送方式在「设置 → 高级」：`auto` 先发文件、失败再试链接，`file` 只发文件，`url` 只发链接。链接有时效，过期就只剩文件可用。

## 出图参数

一次生成多张用 `n`（1–10），单张用默认值 1。还可以给 `quality`、`complexity`、`background`、`output_format`、`output_compression`、`moderation`；`markup` 用来传红笔标注图。文生图、自拍、改图都能用这些参数；自拍和改图只支持 png、jpeg、webp，GIF/SVG 只走文生图。

- GIF：`output_format="gif"`，默认 9 帧、200 毫秒一帧；帧数 2–64，间隔 20–2000 毫秒。超过 16 帧会在日志里提示。
- SVG：`output_format="svg"`，只能出 1 张。只认 `<?xml` 或 `<svg` 开头的真实矢量内容；服务商拿 PNG 顶替会直接报「服务商没有返回 SVG」，不会把这家服务商记成失败。
- GIF 和 SVG 目前只走标准生图接口；对话接口出图和自定义完整地址不参与这两种格式。
- 有的服务商接受了格式参数却仍然回 PNG；插件按实际内容校验，会报「服务商没有返回 GIF / SVG」，不会把静态图当成动图。
- PNG、JPEG、WebP 之间不转码：服务商返回哪种，就按哪种保存和发送。

## 批量生成

批量也走 `generate_image`，不用再记第二个工具名：

- 给 `prompts`：数组里每项是一条提示词。直接写字符串即可；要单独指定这一张的画幅，就写成 `{"prompt": "...", "output": "3:4"}` 这样的对象。
- 只给 `brief`：把一句话交给插件，由默认的快速模型拆成多条提示词。内置模板要求几条的主体一致，角度、景别、光线、构图、风格至少三项不同。

只给 `brief` 或只给 `prompt` 时，张数取 `count`；不传默认 4。给 `prompts` 时张数就是数组长度，超出「批量上限」（默认 8）的部分会截掉。

每一张单独记账：一张失败不影响其他张，任务状态里能看到整体进度；失败会如实告诉用户，重新说一次要什么即可。

画幅从内置的 `1:1,3:4,4:3,16:9,9:16` 里挑。某个画幅重复出现、池里还有没用过的选项时，会被换成没用过的那个，一批图不会全是一个比例。

拆不出来时工具会直接回复「请直接给 prompts」：没有可用的模型、模型调用失败、返回内容里没有能用的提示词，都算这种情况，不会静默失败。

## 提示词策略

所有会影响出图的文字都在设置里，能看见、能改、能清空：

- 「提示词管理」卡片集中放结果通知、自拍前缀、自拍转视频底图、文生图预设、改图预设、视频预设这几段。结果通知填了就是人设加你写的指令，留空就是人设加插件给的最小事实。
- 服务商的 `prompt_template`、自拍转视频底图模板支持 `{{prompt}}` 占位符；留空表示不追加。
- 自拍提示词前缀是一段固定文字，原样拼在描述前面，不做占位符替换。
- 参考图说明的七个角色标签、开头和结尾两句、两条媒体提示，都可以在「提示词管理」里改，留空回到默认。
- 工具描述是写给模型看的用法说明，也跟着代码发布，不在「隐藏提示词」之列；它们不改变出图内容，只说明什么时候用哪个工具。
- 每个任务都保存 `prompt_layers` 与 `final_prompt` 审计字段，方便回看最终提示词。

## WebUI

插件页面提供五个页面：

- 概览：服务商数量、队列情况、画廊统计、最近任务。
- 服务商：「连接」里增删改服务商，「功能链路」里排顺序。
- 任务：只读汇总，一行一个任务（时间、提示词、状态）；批量的进度、失败原因和服务商放在状态的悬停提示里，明细在聊天里看。
- 画廊：按时间倒序，可以按类型筛选、收藏、删除、点开看大图。
- 设置：提示词管理、权限、默认画幅、队列、画廊保留、框架接管。

改动会在右上角提示「有未保存的修改」，点「保存配置」后立即生效；还有任务在跑时会先问一句，确认后才会应用。页面默认浅色，右下角可以切深色，选择会记住。

## 数据存储

数据目录为 Kira 的 `data/plugin_data/kira_plugin_aiimg/`：

- `gallery/`：成功图片文件；`gallery.sqlite3`：画廊索引
- `tasks.sqlite3`：任务记录
- `image_memory.sqlite3`：图片编号与出处
- `recovered/`：画廊写库失败时临时落盘的图，发完仍可手动取回
- `agnes_video/requests.sqlite3`：视频限速账本

## 访问控制

在「设置 → 访问控制 → 白名单」里填名单，一行一个，用户编号和群编号都认：

- 只写编号：这个用户或这个群可以用。
- 写「平台名:编号」：限定平台，比如 `qq:123456`。
- 直接贴 Kira 的会话 ID：比如 `qq:dm:123456`。中间那段是会话类型，不参与匹配，只认平台和最后的编号。
- 群编号写进来后，这个群里所有人都能用。

名单用列表编辑器维护：点「编辑」打开弹窗，输入框里回车逐条添加，也可以「批量粘贴」一次贴多行，空行和重复项会自动跳过。

留空表示不做限制，谁都能用。名单外的人调用工具时会收到「无权使用该功能」，任务状态也只能查自己的。

## 和框架自带生图的关系

本插件定位是取代框架自带的生图。插件运行期间，框架自带的出图写法（`<img>`、`<selfie>`、`<video>` 三个标签）会被摘掉，出图只走本插件的工具，避免同一句话出两次图；其它插件自己注册的同名标签不受影响，比如 NAI 的 `<img>` 照常工作。

只有能接得住的时候才会接管：一个生图服务商都没配时，框架自带那套保持可用；`<selfie>` 还要求先填好自拍参考图，`<video>` 要求配了视频服务商。「设置 → 框架接管」会写明当前是否已接管。

装了本插件不用再去框架设置里关「图片生成」，那个开关留着就行；本插件卸载或停用后自带那套会自己回来。

需要两套并存时，把「设置 → 框架接管 → 取代框架自带的出图标签」关掉（默认开）。关掉后框架自带那套会重新出现。
